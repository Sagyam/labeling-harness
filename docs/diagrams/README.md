# Figures

Four figures, each in three forms. The `.html` is the source; `.svg` and `.pdf` are generated by
`build.py` and should not be hand-edited.

| Figure | Type | Shows |
|---|---|---|
| `ingest-pipeline` | Architecture | Upload or YouTube URL through the five ingestion stages to the built queue |
| `priority-scoring` | Sankey | How the four weighted signals compose `priority_score` |
| `annotation-lifecycle` | State machine | A task from `pending` to `done`, and the four dispositions |
| `data-model` | ER | The six core tables and their cardinality |

## Rebuilding

```bash
python3 docs/diagrams/build.py                 # all
python3 docs/diagrams/build.py data-model      # one
```

Needs `chromium` on `PATH`, and network access on the first run — the font files are cached under
`.fontcache/` (gitignored) and reused after that.

## Which file to use where

- **`.svg`** — the web docs. Referenced from `README.md` and `architecture.md`, renders on GitHub.
  Typography is pulled from Google Fonts at render time, so the file stays small but needs the
  network to look right.
- **`.pdf`** — LaTeX. `\includegraphics[width=\columnwidth]{ingest-pipeline.pdf}`. Fonts are
  embedded, so it needs nothing at build time.
- **`.html`** — edit this, then rebuild.

## House style

Figures are drawn with the `diagram-design` plugin against the **`nepanglish-paper`** profile
(`~/.diagram-design/profiles/nepanglish-paper.md`, selected by the `.diagram-design` marker in the
repository root). It is a print-first skin: white ground, near-black ink, one deep-teal accent used
on at most two elements per figure, and a type ramp sized so nothing falls below 7pt when a figure
is placed at single-column width. Colour is never the only cue — a focal element also carries a
tint fill and a heavier stroke, so the figures survive greyscale printing and colour-blind review.

Every figure is authored at `viewBox` width **560**. That is the number the type ramp is calibrated
against; changing it silently shrinks every label. If a figure will not fit, cut a node rather than
shrink the type.

## Two traps, both already handled by `build.py`

Worth knowing before hand-rolling an export.

**Google's webfont endpoint produces Type 3 fonts.** Rendering a PDF against
`fonts.googleapis.com`'s default (variable, `woff2`) response makes Chromium emit Type 3 fonts,
which IEEE and ACM reject at submission. `build.py` requests the static `.ttf` faces with a legacy
User-Agent and embeds them as base64, which yields subsetted CID TrueType. Verify with
`pdffonts <file>.pdf` — every row should read `CID TrueType` and `emb yes`.

**`→` (U+2192) is outside Google's `latin` subset.** With the webfont it silently falls back to
whatever monospace font the machine has. The full static `.ttf` covers it.

A third trap has no automatic guard beyond the one in `build.py`: a standalone `.svg` is parsed as
strict XML, unlike HTML. A bare `&`, or a `--` inside an `<!-- comment -->`, renders fine in a
browser and then fails to open in Inkscape, Illustrator or LaTeX. `build.py` parses every `.svg` it
writes and fails loudly rather than shipping one.
